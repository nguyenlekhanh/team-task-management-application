### Controller Function Details

**getChecklist**
- Validates taskId
- Verifies group membership
- Returns items ordered by `order` ASC with completer user object
- 401 if unauthenticated, 404 if not member or invalid taskId

**addChecklistItem**
- Validates taskId, title (required, max 500 chars), order (optional, non-negative integer)
- Verifies group membership
- Auto-assigns order (max + 1) if not provided
- Returns 201 with created item (completer: null)
- 400 for validation errors

**updateChecklistItem**
- Validates taskId, itemId
- Validates title (optional, max 500 chars) and order (optional, non-negative integer)
- Verifies group membership
- Updates only provided fields
- Returns updated item with completer
- 400 if no valid fields to update

**deleteChecklistItem**
- Validates taskId, itemId
- Verifies group membership
- Deletes item
- Returns success message

**toggleChecklistItem**
- Validates taskId, itemId, isCompleted (required boolean)
- Verifies group membership
- If completing: sets completedBy=req.user.id, completedAt=NOW()
- If uncompleting: sets completedBy=null, completedAt=null
- Returns updated item with completer user object

### Authorization
- All endpoints require authentication (uses existing `authenticate` middleware)
- All endpoints verify group membership via GroupMember table
- Returns 404 (not 403) for non-members to avoid information leakage
- No additional role checks - all group members can manage checklist (per 5A.1 design)

### Validation
- Title: required for create, optional for update, max 500 chars
- Order: optional, must be non-negative integer
- isCompleted: required boolean for toggle
- Invalid taskId/itemId: 400
- Non-existent task/item: 404
