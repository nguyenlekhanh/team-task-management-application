# Phase 6.7 — Task List Actions & Coverage

## STATUS
COMPLETED

## OBJECTIVE
Make Task List actionable: permission-aware inline Status/Priority/Assignee controls and Delete, using existing APIs only, with safe per-row saving and server-authoritative updates.

## IMPLEMENTATION

**TaskList inline actions** (`frontend/src/pages/TaskList.jsx`)
- Added per-task permission derivation from `groupMembers` + `user.id` (owner/admin/creator/assignee + creatorIsOwner check) — identical logic to TaskDetail 6.4.
- **Status**: select todo/in_progress/completed (overdue NOT selectable, remains derived) → `taskApi.updateStatus`. Display fallback is `TaskStatusBadge`.
- **Priority**: select low/medium/high/urgent → `taskApi.update`.
- **Assignee**: select Unassigned + group members → `taskApi.update`.
- **Delete**: button with native `confirm()`, permission-gated, `taskApi.delete` → list update with pagination edge handling (last item on page >1 moves to previous page).
- Per-row saving state `rowSaving[taskId] = 'status'|'priority'|'assignee'|'delete'` disables relevant controls, sets `aria-busy`, prevents races (same-value or in-flight clicks ignored).
- Errors surface via existing top banner `getApiErrorMessage`; failed updates preserve previous row state.
- Create Task top button fixed: now navigates to `/groups/:groupId/tasks/new` (was stale `setShowCreateModal`).

**UX / Accessibility**
- Row `aria-busy` when saving; selects have `aria-label="Change … for <title>"` and `aria-busy`; delete has `aria-label="Delete task …"`.
- Pagination buttons already had `aria-label`/`min-h`; preserved.
- Overdue derived via shared `isTaskOverdue` helper.

**Backend**
- No new endpoints, no migrations, no realtime events.

## KNOWN LIMITATIONS
- Status `overdue` remains display-only derived state; not selectable (backend supports it but UI treats it as derived).
- No bulk status/priority updates.
- Realtime task list refresh not implemented (Phase boundary); refresh via navigation/filter/pagination.
