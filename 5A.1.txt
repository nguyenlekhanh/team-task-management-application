## API DESIGN

### Checklist Endpoints

#### 1. GET /api/tasks/:taskId/checklist
**Purpose**: List all checklist items for a task
- **Auth**: Required (Bearer token or cookie)
- **Authorization**: User must be member of task's group
- **Params**: None
- **Response**: 
```json
{
  "items": [
    {
      "id": 1,
      "taskId": 5,
      "title": "Design database schema",
      "isCompleted": true,
      "order": 0,
      "completedBy": 2,
      "completedAt": "2024-08-22T10:30:00Z",
      "createdAt": "2024-08-22T10:00:00Z",
      "updatedAt": "2024-08-22T10:30:00Z",
      "completer": { "id": 2, "username": "john", "displayName": "John Doe", "avatarUrl": null }
    }
  ]
}
```
- **Errors**: 401 (unauthenticated), 404 (task not found/access denied)

#### 2. POST /api/tasks/:taskId/checklist
**Purpose**: Add a new checklist item to a task
- **Auth**: Required
- **Authorization**: User must be member of task's group (all members can add)
- **Body**:
```json
{
  "title": "Write unit tests",
  "order": 2  // optional, defaults to end
}
```
- **Validation**: title required, max 500 chars, order >= 0 integer
- **Response**: 201 Created with new item (including completer if completed)
- **Errors**: 400 (validation), 401, 404 (task not found/access denied)

#### 3. PUT /api/tasks/:taskId/checklist/:itemId
**Purpose**: Update a checklist item (title, order)
- **Auth**: Required
- **Authorization**: User must be member of task's group
- **Body**:
```json
{
  "title": "Updated title",  // optional
  "order": 3  // optional
}
```
- **Validation**: title max 500 chars if provided, order >= 0 if provided
- **Response**: 200 OK with updated item
- **Errors**: 400, 401, 404 (item/task not found), 403 (if needed - but all members can edit)

#### 4. DELETE /api/tasks/:taskId/checklist/:itemId
**Purpose**: Delete a checklist item
- **Auth**: Required
- **Authorization**: User must be member of task's group (all members can delete)
- **Response**: 200 OK { "message": "Checklist item deleted" }
- **Errors**: 401, 404 (item/task not found)

#### 5. PUT /api/tasks/:taskId/checklist/:itemId/toggle
**Purpose**: Toggle completion status of a checklist item
- **Auth**: Required
- **Authorization**: User must be member of task's group (all members can toggle)
- **Body**: `{ "isCompleted": true }` or `{ "isCompleted": false }`
- **Behavior**:
  - If `isCompleted: true` and was false: set `completedBy = req.user.id`, `completedAt = NOW()`
  - If `isCompleted: false` and was true: set `completedBy = null`, `completedAt = null`
- **Response**: 200 OK with updated item (including completer user object)
- **Errors**: 400 (isCompleted required), 401, 404

### Implementation Notes
- All endpoints require authentication via existing `authenticate` middleware
- Group membership verified by checking `GroupMember` for `task.groupId` and `req.user.id`
- Consistent with task authorization: all group members can manage checklist
- Return sanitized items with `completer` user object (id, username, displayName, avatarUrl)

## AUTHORIZATION RULES

| Action | Owner | Admin | Creator | Assignee | Member |
|--------|-------|-------|---------|----------|--------|
| View checklist | ✅ | ✅ | ✅ | ✅ | ✅ |
| Add item | ✅ | ✅ | ✅ | ✅ | ✅ |
| Edit item (title/order) | ✅ | ✅ | ✅ | ✅ | ✅ |
| Delete item | ✅ | ✅ | ✅ | ✅ | ✅ |
| Toggle completion | ✅ | ✅ | ✅ | ✅ | ✅ |
| Reorder items | ✅ | ✅ | ✅ | ✅ | ✅ |

**Rationale**: Checklists are collaborative - all group members can contribute. This matches the Phase 4 design: "Member: Create tasks, add/complete checklist items" and "Assignee: Update status, add/complete checklist items".

**Backend enforcement**: All endpoints verify group membership (404 if not member). No additional role checks needed for checklist operations.

## RISKS / EDGE CASES

| Risk | Mitigation |
|------|------------|
| Task deletion | CASCADE delete on Checklist.taskId handles automatically |
| Checklist item deletion | Simple DELETE, no dependencies |
| CompletedBy user deletion | FK SET NULL handles - completer becomes null, item retains completion status |
| Duplicate items | No unique constraint on title - allow duplicates, use order for distinction |
| Ordering conflicts | Use integer `order` field; on add, set to MAX(order)+1; on reorder, update affected items |
| Unauthorized users | All endpoints verify group membership via existing pattern |
| Non-members | Return 404 (not 403) to avoid information leakage |
| Invalid taskId | Return 404 |
| Invalid checklist itemId | Return 404 |
| Empty title | Validation: required, min 1 char |
| Title too long | Validation: max 500 chars |
| Concurrent updates | Optimistic locking not needed for MVP; last-write-wins acceptable |
| Large checklists | Pagination not needed initially (typically < 50 items) |
| CompletedAt timezone | Store as UTC, display in user's local time (date-fns) |
