## ERROR-HANDLING AUDIT SUMMARY

| Area | Audit finding | Action |
|---|---|---|
| **Login failure → axios interceptor** | `POST /auth/login` returns **401** for wrong password; the axios response interceptor treated EVERY 401 as session-expiry → wiped localStorage + `window.location.href='/login'` ⇒ **full page reload on every failed login**, destroying the rendered error message | **FIXED**: interceptor skips auth endpoints (`/auth/login`, `/auth/register`) — login page owns its error UX; protected-request 401s still wipe + redirect |
| **Unhandled controller exceptions** | Express default dev handler leaks **stack traces** to clients under `NODE_ENV=development`; `login` had no try/catch, `getMe` re-threw non-token errors | **FIXED**: global error middleware in `app.js` (safe JSON envelope, server-side logging only); login/getMe wrapped with safe 500 fallbacks |
| **Malformed JSON body** | body-parser SyntaxError surfaced as 500 via new middleware | **FIXED**: middleware classifies `entity.parse.failed` / SyntaxError-400 → clean `{error:'Invalid JSON body'}` 400 |
| **Garbage date fields persisted** | `POST/PUT task` accepted non-date `startDate`/`dueDate` values (e.g. objects) → stored, rendered later as 'Invalid Date' in UI | **FIXED**: date validation in createTask/updateTask (`400 Invalid start date or due date`) |
| **Axios has no timeout** | hanging requests left spinners forever | **FIXED**: 15 s default timeout; timeouts surface as 'Request timed out…' |
| **Socket auth-expiry reconnect loop** | expired-token sockets retried reconnect indefinitely | **FIXED**: SocketContext handles `connect_error` for auth-classified reasons — closes socket, clears stale auth, redirects to /login (mirrors REST path; per 5D.1 §4 design) |
| **No React error boundary** | a render exception blanked the entire app | **ADDED**: minimal root `ErrorBoundary` (Tailwind-styled card, reload recovery, logs only `error.message`, does NOT intercept API errors) |
| markAsRead optimistic state | verified correct already (await-before-update) | no change |
| Form duplicate-submission guards | Login/Register/Profile/moderators/chat/comment all disable while pending | verified, no change |
| Empty/loading/error states | all major lists already differentiate (verified across pages/components) | no change |
| Backend logging | `err.message` only everywhere; never tokens/headers/passwords | verified, no change |

## API ERROR CONTRACT (now enforced & tested)
- Consistent envelope: `{ "error": "<safe message>" }`
- Status usage: 400 validation · 401 auth · 403 permission (clear role wording) · 404 blind not-found · 409 duplicates · 500 generic
- Client errors from body-parser map to 400 ('Invalid JSON body')
- Global handler normalizes everything uncaught to `{error:'Internal server error'}` 500
- **Leak patterns asserted absent** in every tested error body: stack frames, raw SQL, node_modules paths, Sequelize/validation class names, file:line references
- Frontend helper added: `getApiErrorMessage(error, fallback)` in services/api.js — distinguishes timeout / network failure / server message / fallback

## AUTHENTICATION FAILURE BEHAVIOR
- Protected-request 401 → storage wipe → `/login` (unchanged, no loops observed: PublicRoute sees cleared state)
- Auth-endpoint 401 → inline form error only (fixed reload bug)
- Socket handshake auth failures → same classification list as backend (`Authentication required` / `Invalid token` / `Token expired` / `User not found`) → close + wipe + redirect; other connect_errors keep standard reconnection

## SESSION RESTORE
- Startup reads localStorage only (no network) — cannot hang; malformed stored JSON is cleaned up (pre-existing); expired tokens surface on first API call via interceptor. Documented as intended behavior.

## REALTIME ERROR BOUNDARIES
- All event handlers validate required fields before state updates (`item.id` guards in useNotifications/ChatPanel/CommentSection); malformed frames ignored
- Presence/notification/emitter failures remain best-effort and cannot break REST or socket lifecycle (re-verified by full battery)

## CONCURRENCY / RACES
- Verified existing guards: pending flags block double-send on all mutation buttons; await-before-state-update ordering in notification mutations prevents false-authoritative states; realtime handlers merge by primary key so REST/socket races converge; logout closes socket via SocketProvider effect
