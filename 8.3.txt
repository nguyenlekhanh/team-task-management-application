# Phase 8.3 - Forms, Buttons, Modal Touch-Target & Spacing Polish

## STATUS
COMPLETED

## OBJECTIVE
Small consistency + mobile-usability pass over interactive controls (forms, buttons,
modals, selects, icon buttons). Fix only real issues confirmed by audit; leave adequate
components alone. Includes one REAL FUNCTIONAL BUG the audit discovered and fixed.

## AUDIT PERFORMED (methodology + findings)
Code-level class inspection of every listed component against the project's own
conventions (44px primary targets from 6.3/6.6, focus-visible rings, px-4 py-2 buttons,
px-3 py-2 inputs, space-y-4 forms) and 320–430px viewport math (modal ≈ 288–398px usable).

### Real problems found (and fixed)
- **P0 FUNCTIONAL BUG — TaskDetail "Delete Task" did nothing**: the button called
  `setShowDeleteConfirm(true)` but NO confirmation UI was ever rendered (dead state),
  and the real `handleDelete` (with its confirm() guard) had zero callers. The Delete
  Task button silently no-ops — broken interaction left over from the 6.x sidebar
  restructure. FIXED: button wired to the existing confirm()-guarded `handleDelete`,
  dead `showDeleteConfirm` state removed, and the post-delete hard reload
  (`window.location.href`) replaced with client-side `navigate()` (project pattern
  from 6.5). Button also gained min-h-[44px] + focus ring.
- **P1 Modal action rows cramped at 320px** (3 occurrences of one pattern):
  AddMemberModal, Create Group modal, TaskForm actions used `flex space-x-3` with two
  flex-1 buttons ≈ 96px each and 36px height. FIXED with one consistent pattern:
  `flex flex-col sm:flex-row gap-2 sm:gap-3 sm:space-x-3` + `min-h-[44px]` — stacked
  full-width on phones, identical row at sm+.
- **P2 Bare modal close buttons**: 24px icon-only, no aria-label, no ring, no hover
  surface (Groups modal + AddMemberModal). FIXED: `p-1.5 rounded hover:bg-gray-100
  min-h-[36px] min-w-[36px]` + `aria-label="Close"` + focus-visible ring
  (Navbar-hamburger pattern).
- **P3 ChecklistItem edit/delete icon buttons**: ~22–24px targets, `title=` only
  (not accessible names). FIXED: `p-1.5` (≥36px target), `aria-label="Edit/Delete
  checklist item <title>"`, focus-visible rings, hover surfaces.
- **P4 Destructive text buttons without targets/rings**: GroupDetail member "Remove"
  (≈28px) and Danger-Zone "Delete Group" (36px, no ring). FIXED: min-h-[36px] +
  focus-visible rings; confirm() dialogs preserved (accidental-deletion protection).
- **P5 Login/Register controls below the project's own 44px convention**: inputs and
  submit at py-2 ≈ 36px while the Checklist input already got min-h-[44px] in 6.6 —
  inconsistent on the two pages where mobile typing happens most. FIXED: all 7
  controls in Login/Register gained min-h-[44px]. NOT applied globally (see below).

### Verified adequate — INTENTIONALLY LEFT UNCHANGED
TaskList inline row selects (min-h-[32px] + aria-labels + aria-busy, dense-table
pattern from 6.7); TaskList Delete (already min-h-[32px] + ring + confirm + aria-label);
TaskDetail status/assign sidebar selects; pagination buttons (min-h-[36px], 6.6/8.2);
NotificationBell (p-2 + aria-label + ring); NotificationItem delete (already

CommentItem dropdown rows; Checklist checkbox; Navbar (8.1); Dashboard (7.x);
modal/page form inputs other than Login/Register (36px with 16px text is within
platform norms — no blanket min-h sweep, per phase rules).
