| isRead | TINYINT(1) / BOOLEAN | NO | 0 (false) | Read/unread state |

| metadata | JSON | YES | - | Flexible payload (serialized as TEXT in SQLite) |

## DOCUMENTED DEVIATION FROM 5C.1.txt

**Issue**: Sequelize naming collision between attribute and association alias.
The 5C.1.txt design specifies BOTH:
- a column named `message` (TEXT NOT NULL) on the Notifications table, AND
- an association `Notification.belongsTo(Message, { as: 'message', foreignKey: 'messageId' })`

Sequelize throws a fatal error at model-load time:
```
Error: Naming collision between attribute 'message' and association 'message' on model Notification.
```
This is a concrete inconsistency in the design document (the DB schema itself is fine; only the
Sequelize association alias conflicts).

**Resolution (minimal deviation)**:
- Database schema kept EXACTLY as designed (all 14 columns unchanged, FK names unchanged)
- Only the association alias renamed from `'message'` to `'sourceMessage'`
- All other aliases (`recipient`, `sender`, `task`, `group`) are exactly as designed

Impact: application code in 5C.3 must use `include: [{ model: Message, as: 'sourceMessage' }]`.
No other architectural change.

## KNOWN ISSUES
1. **Association alias deviation**: `sourceMessage` instead of `message` (see Deviation section). Documented; no functional impact.
2. **SQLite stores JSON as TEXT**: transparent serialization handled by Sequelize; no queryable JSON functions inside metadata (acceptable for MVP).
3. **No unique/dedup constraint**: DEADLINE_APPROACHING deduplication is deferred to trigger logic in 5C.3 (per 5C.1 design decision).
4. **Pre-existing environment notes** (not caused by this phase): JWT expiry of 15 min; server process management requires nohup/process manager in production.
