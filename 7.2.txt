# Phase 7.2 - Team Productivity Detail

## STATUS
COMPLETED

## OBJECTIVE
Add the "team" dimension the 7.1 overview lacked: a per-group productivity breakdown on the
Dashboard (total / to do / in progress / completed / overdue / due soon / unassigned /
completion rate), computed server-side in a single request and rendered read-only with links
into existing pages.

## WHAT WAS IMPLEMENTED

### Backend (smallest additive change — same precedent as 6.5's `scope` param)
`GET /api/groups?include=stats` — each group in the user's membership-scoped list gains a
`stats` object:
```json
"stats": { "total": 7, "todo": 4, "inProgress": 1, "completed": 2,
           "overdue": 1, "dueSoon": 1, "unassigned": 1, "completionRate": 29 }
```
- `groupController.getUserGroups` gained an optional stats branch: after the existing
  membership query, ONE additional `Task.findAll` over `groupId IN (user's groups)` selecting
  only `groupId, status, dueDate, assigneeId` (attributes-only; no includes; no per-group
  fan-out), reduced in JS via `computeGroupStats`.
- Derivation rules (consistent with 6.6/7.1 canonical definitions):
  - todo/inProgress/completed = exact stored status counts
  - overdue = `dueDate < now && status !== 'completed'` (derived; stored status 'overdue' not
    additionally counted — overdue remains a display derivation)
  - dueSoon = due within next 24h and not completed (same rule as 7.1)
  - unassigned = `assigneeId == null && status !== 'completed'` (OPEN unassigned work)
  - completionRate = `Math.round(completed / total * 100)`; 0 for empty groups
- Without the param the response is unchanged (no `stats` key) — backward compatible.

### Frontend
- `services/api.js`: `groupApi.list(params)` now accepts optional params.
- `pages/Dashboard.jsx`: overview fetches `groupApi.list({ include: 'stats' })`; the 7.1
  "My Groups" chips card was upgraded to "Team Productivity by Group" — responsive table
  (overflow-x-auto per TaskList convention) with one row per group: name link + role badge
  (getRoleColor), count columns (Overdue red when > 0, Due Soon orange when > 0), completion
  progress bar (`role="progressbar"` with aria-valuenow/min/max/label) and "View all groups →"
  link. Defensive rendering: rows show "—" if `stats` is absent (older backend) so the
  overview degrades gracefully instead of crashing.
- All 7.1 cards preserved (stat strip, Recent Tasks/Notifications, User Info, Health,
  Quick Actions).

## SECURITY / AUTHORIZATION VERIFICATION
- Identity server-derived: group list comes from the user's own GroupMember rows; the client
  cannot name any group. Stats aggregate ONLY over those groups — a non-member's group can
  never appear (isolation asserted).
- Aggregated rows are the same data the user could already page through via
  GET /api/groups/:id/tasks — no new exposure surface.
- Unauthenticated → 401 on both param variants (asserted).
- No identity fields accepted from the client anywhere in this change.

## KNOWN LIMITATIONS
- Snapshot only (mount-time); no realtime dashboard refresh (consistent with 7.1 intent).
- Stats include every task in the group (no pagination) — single attributes-only query makes
  this O(1) requests regardless of group count; fine at MVP scale (<10k rows/instance).
- No trends/history (would need aggregation tables — explicitly out of scope).
- Table scrolls horizontally on narrow viewports (overflow-x-auto convention; full mobile
  redesign remains Phase 9).
